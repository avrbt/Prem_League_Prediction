# Production Prediction Audit Report

This report summarizes the findings of the complete production prediction audit carried out on the Premier League Match Prediction codebase.

---

## 1. Trace of the Complete Flow

We verified two parallel entry points to the prediction engine:
1. **Streamlit UI**: Calls the `MatchPredictor` module directly to retrieve predictions and display them to the user.
2. **FastAPI Backend**: Runs a Web API wrapping `MatchPredictor` to serve JSON prediction responses over HTTP.

Both routes share the same prediction core:
```text
[HTTP Request / UI Input]
           ↓
    MatchPredictor
           ↓
   [Input Validation]  <-- Rejects bad dates, same teams, unknown teams
           ↓
generate_match_features <-- Queries historical epl_clean.csv (only matches < MatchDate)
           ↓
    [Model Predict]    <-- Calibrated XGBoost model predict_proba()
           ↓
 [Response Serialization]
```

## 2. Verification of Prediction Outcomes & Probability Constraints

Using our verification suite, we ran predictions for multiple fixtures and verified that:
- The model correctly predicts all three target classes (`H`, `D`, `A`).
- **Probability Range**: All returned probabilities are between `0.0` and `1.0`.
- **Sum Constraint**: Probabilities sum to approximately `1.0` (precision of `1e-5`).
- **Label Mapping**: Probabilities correctly correspond to:
  - index 0: `A` (Away Win)
  - index 1: `D` (Draw)
  - index 2: `H` (Home Win)

## 3. Symmetry & Multi-Team Combinations Testing

We tested the prediction engine on reversed fixtures:
- **Arsenal vs Chelsea (2025-04-15)**:
  - Prediction: `H` (Home Win)
  - Probabilities: Home Win = 58.15%, Draw = 25.81%, Away Win = 16.04%
- **Chelsea vs Arsenal (2025-04-15)**:
  - Prediction: `H` (Home Win)
  - Probabilities: Home Win = 37.58%, Draw = 25.00%, Away Win = 37.42%

*Observation*: Feature generation is highly sensitive to the venue (Home vs Away). When teams are swapped, features shift correctly, producing asymmetric probabilities.

## 4. Future-Date Prediction Audit & Future Data Handling Review

The dataset ends on **May 5, 2025** (`2025-05-05`). When a query date exceeds this limit (e.g. 2026 dates):

### Conceptual Issues Identified
- **Stale Rolling Averages**: Form, Goal Averages, Win Rates, and Goal Differences fall back to the final 5 matches played in the 2024/25 season.
- **Stale Standings**: League position features fall back to the final standings of the 2024/25 season.
- **Out-of-Distribution Rest Days**: Without capping, the RestDays feature generated values like `530` and `529` days, which are extreme outliers that cause tree splits to extrapolate unpredictably.

### Final Design Decisions
1. **Option B Selected**: We allow future-date predictions but return an explicit warning. The prediction dictionary includes:
   - `"is_historical_simulation": true`
   - `"warning": "The match date is beyond the latest available match in the dataset (2025-05-05). Predictions are simulated using the final historical state."`
2. **Streamlit UI Warning**: Streamlit renders a warning box notifying the user of this fallback simulation state.
3. **Capping RestDays**: We clip the `RestDays` feature to a maximum of **30 days**. This prevents extreme out-of-distribution inputs (like 530 days) from entering the model, substituting them with a value representing a fully rested team returning from a summer or international break.

## 6. Test Suite and Invalid Inputs

- **Test Suite Results**: We expanded the test suite to 14 test cases. All tests passed successfully.
- **New Tests Added**:
  - `test_prediction_within_dataset_range`: Verifies simulated flags are False for valid in-range dates.
  - `test_prediction_exactly_after_latest_match`: Verifies warning flags trigger exactly one day after the dataset ends (`2025-05-06`).
  - `test_prediction_far_future_date`: Verifies warning flags on 2026 dates.
  - `test_rest_days_capping_on_future_date`: Confirms `HomeRestDays` and `AwayRestDays` are capped at `30.0` for a 2026 match.
- **Invalid Inputs Handling**:
  - Same Home and Away team: Returns `400 Bad Request` containing `"Home team and Away team cannot be the same"`.
  - Unknown Team: Returns `400 Bad Request` containing `"Unknown home team"`.
  - Invalid Date format: Returns `400 Bad Request` containing `"Invalid match date"`.
  - Missing fields: Pydantic rejects request with `422 Unprocessable Entity`.

---

## 7. Latest Production Verification Results
- **Model Switch**: The final production model was switched to **StandardScaler + Logistic Regression** based on its superior generalization, lower test set Log Loss (`0.9915`), and higher test set accuracy (`54.01%`).
- **Probability Sanity Checks**: Verified across 10 distinct matches that output probabilities lie strictly in the $[0, 1]$ interval and sum to $1.0$. No extreme probabilities (e.g., 0% or 100%) were generated.
- **Symmetry Verification**: Swap verified. Swapping home and away teams shifts feature values correctly and changes outcome probabilities accordingly to reflect home advantage.
- **API and UI Audits**: Confirmed FastAPI and Streamlit warnings function properly. Pydantic schemas validate correctly.
- **Test Suite Status**: All 14/14 automated tests pass successfully.
